Dependency Map: File by File Analysis

This section details the dependencies between the files in your FastAPI project. Understanding these relationships helps you anticipate the impact of changes.

  • "Depends On (Imports)": Lists files/modules from your app directory that this file imports and relies upon.
  • "Imported By (Dependents)": Lists files/modules from your app directory that import this file and would therefore be affected by changes.

1. app/database/db.py

  • Purpose: Handles SQLAlchemy engine, session, and Base for ORM models. Provides get_db dependency.
  • Depends On (Imports):
    • sqlalchemy (external library)
  • Imported By (Dependents):
    • app/main.py (to create tables)
    • app/models/students.py
    • app/models/teachers.py
    • app/models/courses.py
    • app/models/associations.py
    • app/routers/std_router.py
    • app/routers/tchr_router.py
    • app/routers/crs_router.py
    • app/routers/enrollment_router.py
  • Impact of Change: Changes here (e.g., database URL, session configuration) will impact all parts of your application that interact with the database. This is a foundational file.

2. app/models/associations.py

  • Purpose: Defines the SQLAlchemy association table for the many-to-many relationship between students and courses.
  • Depends On (Imports):
    • app.database.db (for Base.metadata)
  • Imported By (Dependents):
    • app/models/students.py
    • app/models/courses.py
    • app/main.py (implicitly, as main.py imports app.models to register all models with Base.metadata)
  • Impact of Change: Changes to this table structure will impact students.py and courses.py models, and potentially enrollment_crud.py and enrollment_router.py if the way enrollments are handled fundamentally changes.

3. app/models/students.py

  • Purpose: Defines the SQLAlchemy ORM model for the students table.
  • Depends On (Imports):
    • app.database.db (for Base)
    • app.models.associations (for student_course_association)
  • Imported By (Dependents):
    • app/crud/student_crud.py
    • app/crud/enrollment_crud.py
    • app/main.py (implicitly, via app.models import)
  • Impact of Change: Changes to Student model (e.g., adding/removing columns, changing relationships) will impact std_schema.py, student_crud.py, enrollment_crud.py, and any router (std_router.py, enrollment_router.py) that deals with student data directly or indirectly. Requires database migration or recreation.

General Principles for Changes:

  • Changes in models/ or schemas/: These are usually propagated "upwards" to crud/ functions and then to routers/. If you change an ORM model, you must update its corresponding Pydantic schema and any CRUD functions or router endpoints that use it. Model changes often imply database migrations (though for SQLite in development, you might just delete std_tchr.db and let Base.metadata.create_all rebuild).
  • Changes in crud/: These are propagated to the routers/ that call them. If a CRUD function changes its signature or return type, the router calling it must be updated.
  • Changes in routers/: These affect the API's exposed endpoints and how they behave. No other Python files within the project depend on a router, but your API consumers (frontends, other services) do.
  • Changes in database/db.py: These are foundational and impact almost everything. Tread carefully here.
