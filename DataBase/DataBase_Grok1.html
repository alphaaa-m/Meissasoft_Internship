1. Database Fundamentals

What is a Database?

A database is a structured collection of data managed by a Database Management System (DBMS). It ensures efficient storage, retrieval, and management, supporting applications like e-commerce, banking, and social media.

Uses of Databases in Real Life

  • E-commerce: Managing product catalogs, orders, and payments (e.g., Amazon).
  • Healthcare: Storing patient records and medical histories.
  • Banking: Handling transactions and account details.
  • Social Media: Storing user profiles, posts, and connections.
  • Logistics: Tracking shipments and inventory.

Database Terminology

  • Data: Raw facts (e.g., numbers, text).
  • Record: A row in a table representing a single entry.
  • Field: A column in a table storing a specific attribute.
  • Table: A collection of records with a defined structure.
  • Schema: Blueprint defining tables, fields, and relationships.
  • Attribute: A property of an entity (e.g., column name).
  • Tuple: A single row or record in a table.

Types of Databases

  • Relational (SQL): Structured, table-based (e.g., MySQL, PostgreSQL).
  • NoSQL: Flexible, schema-less:
    • Document: JSON/BSON data (e.g., MongoDB).
    • Key-Value: Simple key-value pairs (e.g., Redis).
    • Graph: Relationship-focused (e.g., Neo4j).
    • Column-Family: Column-based storage (e.g., Cassandra).
  • In-memory: Fast, RAM-based (e.g., Redis).
  • Time-series: Optimized for time-stamped data (e.g., InfluxDB).
  • NewSQL: Scalable SQL databases (e.g., CockroachDB).

2. Relational Databases & SQL

Basic SQL

SQL (Structured Query Language) is used to manage and query relational databases.

DDL (Data Definition Language)

  • CREATE: Defines new database objects (e.g., tables).
  • ALTER: Modifies existing objects.
  • DROP: Deletes objects.
  • TRUNCATE: Removes all records from a table.
CREATE TABLE employees (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    salary DECIMAL(10,2)
);

DML (Data Manipulation Language)

  • SELECT: Retrieves data.
  • INSERT: Adds new records.
  • UPDATE: Modifies existing records.
  • DELETE: Removes records.
INSERT INTO employees (id, name, salary) VALUES (1, 'Alice', 75000);

DCL (Data Control Language)

  • GRANT: Assigns permissions.
  • REVOKE: Removes permissions.

TCL (Transaction Control Language)

  • COMMIT: Saves a transaction.
  • ROLLBACK: Reverts a transaction.
  • SAVEPOINT: Sets a transaction checkpoint.

SQL Querying

  • WHERE: Filters rows (e.g., WHERE salary > 50000).
  • ORDER BY: Sorts results (e.g., ORDER BY salary DESC).
  • LIMIT/OFFSET: Restricts rows returned.
  • AS: Creates aliases for columns/tables.
  • Aggregate Functions: COUNT(), SUM(), AVG(), MAX(), MIN().
  • GROUP BY: Groups rows for aggregation.
  • HAVING: Filters grouped results.
  • LIKE: Pattern matching (e.g., WHERE name LIKE 'A%').
  • Subqueries: Nested queries for complex logic.
  • CASE: Conditional logic in queries.

Joins

  • INNER JOIN: Matches rows from both tables.
  • LEFT JOIN: Includes all rows from the left table.
  • RIGHT JOIN: Includes all rows from the right table.
  • FULL OUTER JOIN: Includes all rows from both tables.
  • Self Join: Joins a table with itself.
  • Cross Join: Cartesian product of two tables.
SELECT e.name, d.department
FROM employees e
INNER JOIN departments d ON e.dept_id = d.id;

3. Database Design

ERD (Entity-Relationship Diagrams)

ERDs visualize entities, attributes, and relationships.

Keys

  • Primary Key: Uniquely identifies a record.
  • Foreign Key: Links to a primary key in another table.
  • Candidate Key: Potential primary key.
  • Composite Key: Multiple columns as a primary key.

Referential Integrity

Ensures foreign keys reference valid primary keys.

Relationships

  • One-to-One: Single record links to one other (e.g., user ↔ profile).
  • One-to-Many: One record links to multiple (e.g., customer → orders).
  • Many-to-Many: Multiple records link to multiple (e.g., students ↔ courses, via junction table).

Normalization

Reduces redundancy and ensures data integrity.

  • 1NF: No repeating groups, atomic values.
  • 2NF: 1NF + no partial dependency.
  • 3NF: 2NF + no transitive dependency.
  • BCNF: 3NF + stricter key constraints.

Denormalization

Introduces redundancy for performance (e.g., caching aggregates).

Surrogate vs Natural Keys

Surrogate: Artificial IDs (e.g., auto-increment). Natural: Business data (e.g., SSN). Surrogates are stable; naturals are meaningful but may change.

Schema Design Best Practices

  • Use clear, consistent naming conventions.
  • Enforce data types and constraints.
  • Plan for scalability and indexing.
  • Document relationships and constraints.

4. Transactions & Concurrency

What is a Transaction?

A sequence of operations treated as a single unit.

ACID Properties

  • Atomicity: All or nothing execution.
  • Consistency: Maintains database integrity.
  • Isolation: Transactions are independent.
  • Durability: Committed changes are permanent.

Concurrency Issues

  • Dirty Read: Reading uncommitted data.
  • Non-repeatable Read: Inconsistent data within a transaction.
  • Phantom Read: New rows appear during a transaction.

Isolation Levels

  • Read Uncommitted: Allows dirty reads.
  • Read Committed: Prevents dirty reads.
  • Repeatable Read: Prevents non-repeatable reads.
  • Serializable: Highest isolation, prevents phantoms.

Locks

Pessimistic: Locks data during transactions. Optimistic: Assumes conflicts are rare, checks at commit.

Deadlocks

When transactions wait on each other’s locks. Resolved via timeouts or detection algorithms.

5. Indexing & Performance Tuning

What is an Index?

A data structure to speed up queries (e.g., B-Tree, Hash).

Types of Indexes

  • B-Tree: Balanced tree for range queries.
  • Hash: Fast for exact matches.
  • Composite: Indexes multiple columns.
  • Unique: Enforces uniqueness.
  • Full-Text: Optimized for text searches.

Pros and Cons of Indexes

Pros: Faster queries. Cons: Slower writes, increased storage.

Query Optimization

  • Execution Plan: Analyze query steps with EXPLAIN.
  • Caching: Store frequent query results.
  • Partitioning: Split tables for efficiency.
  • Sharding: Distribute data across servers.
  • Materialized Views: Precomputed query results.
EXPLAIN SELECT * FROM employees WHERE salary > 50000;
